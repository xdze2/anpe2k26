# Rate gate — per-service throttle — 2026-05-08

## Problem

`anpe step summarize_ddg` was launching 4 concurrent workers, each firing an
LLM call immediately. All four hit Mistral's 429 rate limit simultaneously,
each retried with the same backoff delay, and all four hit 429 again on the
next attempt — a thundering herd. The per-call retry loop inside
`summarize.py` was never going to fix this because it operates on a single
call, not on the concurrency level.

## Root cause framing

The binding constraint is **calls per minute**, not simultaneous connections.
A semaphore limiting concurrency to 1 would serialize callers but still allow
back-to-back calls with zero gap. What is needed is a minimum interval between
consecutive requests to the same external service.

## Design

`RateGate(min_interval_s)` in `anpe/engine/rate_gate.py`:

- Holds an asyncio `Lock` and a `_last_call` timestamp.
- `acquire()` takes the lock, computes the remaining wait since the last call,
  sleeps if needed, then records the new call time before releasing.
- The lock serializes callers: while one caller sleeps inside `acquire()`,
  others queue behind it. When the first caller exits, the next one enters and
  finds `_last_call` already fresh — so it too sleeps for the full interval.
  This prevents burst re-entry after the sleep.

`NoGate` is a no-op for steps with no external rate limit.

Shared instances live in `anpe/engine/steps/api_throttles.py` — one per
external service. Steps that share a quota (here: `summarize_ddg` and `eval`
both hit Mistral) reference the same instance.

```
MISTRAL = RateGate(min_interval_s=2.0)   # ~30 req/min free tier
DDG     = RateGate(min_interval_s=1.0)
SIREN   = RateGate(min_interval_s=1.0)
```

Each step declares `rate_gate = api_throttles.MISTRAL` (etc.) as a class
attribute. The runner calls `gate.acquire()` before each `work()` call,
reading the gate directly off the step — no string lookup, no dict.

## Changes

**`anpe/engine/rate_gate.py`** (new) — `RateGate` and `NoGate`.

**`anpe/engine/steps/api_throttles.py`** (new) — module-level singleton
instances `MISTRAL`, `DDG`, `SIREN`, `NONE`.

**`anpe/engine/steps/base.py`** — `Step` protocol gains
`rate_gate: RateGate | NoGate`.

**Each step** — `rate_gate = api_throttles.<X>` class attribute added.

**`anpe/engine/runner.py`** — `gate = getattr(step, "rate_gate", NoGate())`
then `await gate.acquire()` before `step.work()`. The `gates` constructor
parameter (string-keyed dict, an earlier design) was dropped entirely.

**`docs/specs/13_data_engine.md`** — `rate_limiter` entry in "What each step
declares" rewritten as `rate_gate`, with an explicit note that the constraint
is calls per minute (minimum interval), not concurrency.

## Status

- 37 engine tests pass.
- The per-call retry loops in `summarize.py` and `eval.py` are kept as a
  second line of defence for genuine transient spikes, but should rarely
  trigger now.
